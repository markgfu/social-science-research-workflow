# 详细能力说明

本项目将研究阶段诊断、经济学文献综述和论文写作组合为三个可分别使用的 skill。能力来自技能指令与参考资料；实际检索、全文读取、统计计算和文件输出取决于运行环境中的工具、材料与权限。

## 从当前任务选择入口

| 你现在的情况 | 建议入口 | 先提供什么 |
| --- | --- | --- |
| 只有一个大方向，不清楚下一步 | `social-science-research-workflow` | 兴趣现象、研究对象、已有材料和限制 |
| 想建立经济学文献地图或理论谱系 | `economics-literature-review` | 工作问题、范围、已有论文及允许的访问方式 |
| 需要判断某篇论文是否相关 | 工作流 `reading` 速读 | 论文元数据、摘要或全文；明确可访问范围 |
| 需要精读并支撑核心主张 | 工作流 `reading`；经济学谱系任务用文献技能 | 正确版本的全文、阅读目的和待核对问题 |
| 已有文献和证据，准备写成综述 | 文献技能，满足证据门槛后交接写作技能 | 已经人工接受的 A 级笔记和拟讨论的主张 |
| 已有草稿，主要问题是结构与表达 | `research-paper-writing` | 草稿、目标章节、已有结果和不能改动的事实 |
| 不确定设计、机制或稳健性是否成立 | 工作流 `validation` | 设计、识别目标、假设、数据说明与已有检验 |
| 需要汇报、图表解释或求助材料 | 工作流 `presentation` | 听众、目的、图表、事实与希望获得的反馈 |

## 七种工作模式

### literature：发现和组织文献

先确定研究问题、文献范围、纳入排除标准、语言和日期边界，再拆解对象、关系、机制、场景及方法词，组织查询和引文追踪。

可形成检索日志、候选集、枢纽来源及其选择理由、文献簇、共识与分歧、排除理由和下一轮查询。输出按问题或机制组织。没有完成相应检索时，不将“暂时未找到”写成“没有研究”。

### reading：选择阅读深度并提取证据

速读用于相关性筛选、讨论准备和临时地图。精读用于支撑核心主张、核对关键设计或用户要求的逐页验证。仅有摘要时，只形成摘要可支持的初筛卡。

精读笔记涵盖研究问题、动机、设计、数据、发现、贡献、限制、原文锚点、对当前研究的用途及后续行动。区分作者原有主张、阅读者解释、跨文献综合和研究者推断。核验到哪一层就记录到哪一层；不会因打开了 PDF 就自动提升证据等级。

### writing：维护研究论证的承接关系

检查以下模块是否讨论相同对象、范围与研究目标：

```text
研究问题 → 文献动机 → 背景 → 数据 → 研究设计 → 结果主张
```

问题过大时收敛对象与边界；动机缺少文献支持时补查；背景带来识别威胁时进入设计或限制；数据区分样本形成过程与变量定义；设计解释选择理由、实施和核心假设。正文修改按实际论证需要组织段落。

### validation：从威胁选择检验

围绕目标量和选择过程，检查测量、混杂、互为因果、样本选择、溢出、时间错配等实际威胁，再讨论匹配的验证证据。

可建立“威胁—假设—现有证据—缺失证据—主张影响”表，以及稳健性检验计划。检验要说明所针对的威胁、改动、预期、结果及其解释。异质性检查组间差异与不确定性；机制需要可区分预测和竞争解释。方法名称本身不构成设计有效性的证明。

这部分提供设计诊断与验证规划。执行估计、运行代码或生成检验结果，需要实际数据、计算工具及相应任务授权。

### presentation：让听众理解发现与边界

图表说明交代问题、样本、时间、单位、编码和不确定性，再解释总体模式、关键细节及研究含义。表格说明行列结构、规格变化、核心估计量与不确定性。

汇报围绕研究问题、重要性、证据、可信发现、主要限制和所需反馈组织。研究求助 brief 保留一个主要请求，说明困难、已尝试的办法、材料与希望对方采取的动作。实际制作 PPT、PDF 或图像需要相应格式工具。

### training：按明确需求训练

仅在用户要求训练或复盘时启动。先定位检索、阅读、问题收敛、设计、写作或沟通瓶颈，再设定可重复动作、真实材料、可观察产物与复盘标准。每个周期据结果调整主要变量，不强制固定周数或时长。

### full：跨阶段推进并保留回退路径

维护从想法、候选问题、文献发现、阅读提取、人工审核、综合与动机、数据材料、设计、验证到成稿展示和反馈修改的阶段状态。每轮优先处理最能降低当前不确定性的动作。

研究问题、关键文献、样本或设计变化时，识别哪些主张、图表、引用和章节需要回退检查。长任务保留工作记录、版本、决定理由与未解决事项。

## 经济学文献技能的专项深度

### 模型谱系单元

对每篇相关理论论文，恢复以下关系并保留全文依据：

```text
前身模型
→ 继承的基准假设
→ 发生变化的假设
→ 新增变量或约束
→ 经济机制
→ 新的均衡、命题、福利或比较静态结果
```

时间先后不能单独证明模型继承。若属于阅读者的解释，应明确标记并提供依据。模型比较关注变化怎样导致结果变化；文献年份和引用数量只作为相应的背景信息。

### 可追溯的研究材料

视任务需要，保留查询记录、候选导出、规范来源清单、每篇来源笔记、谱系表、综合表、审核状态和主张—证据台账。以 DOI 或稳定标识去重；已有 Zotero 记录时保留 citekey 和相关标识，未经请求不覆盖人工笔记。

### 从综合到成稿

正式综合使用已人工接受且达到 A 级的来源笔记。按问题、谱系或机制展开，比较共同基准、实质改动、支持与矛盾结果。候选缺口还需检查可能推翻它的文献或检索结果。满足证据条件后，可交接写作技能组织成稿。

## 写作技能的专项深度

写作技能按任务读取摘要、引言、相关研究、方法、实验或结果、结论等章节参考；另有段落连贯性、审稿检查及写作示例资料。

修改时先明确文章主张，再核对每段的任务、证据、术语和衔接。反向提纲用于从正文恢复论证结构，查找重复和游离内容。摘要、引言和结果讨论中的重要主张必须与实际证据相称。结果讨论需要解释发现改变或限定了什么认识。

章节参考与示例主要来自 ML/CV/NLP 场景。用于经济学和其他社会科学时，按假设、制度背景、识别、机制、数据及结果调整。共享作者判断规范优先于通用模板；不强制每段使用同一开头或结尾。

用户要求成稿时，默认给出完成后的文字及必要引用。用户要求审稿、解释改动或逐段分析时，再提供相应分析；内部检查不默认作为额外交付物。

## 证据与人工判断怎样配合

| 情况 | 可支持什么 | 接下来做什么 |
| --- | --- | --- |
| C 级：元数据、检索结果、二手提及 | 来源发现 | 获取并核验正式摘要或全文 |
| B 级：核验正式摘要 | 初筛、暂定描述 | 如需核心使用，核验相关全文并保存锚点 |
| A 级：核验相关全文或一手材料，有定位 | 具备核心使用所需的证据层级 | 仍需核对具体主张与人工审核状态 |
| `waiting-review` | AI 已提取，尚待人工审核 | 人工接受、修改或拒绝 |
| `accepted + A` | 支持符合原文边界的核心综合与成稿 | 持续核对主张、锚点和解释边界 |

核验全文与人工接受是两项条件。模型不会自行代替人工接受，也不会用摘要补造模型、数据、机制或结果。

## 一次任务可以交付什么

以下是按任务选取的产物示例，不是每次必须创建的固定文件清单。

| 产物 | 记录内容 |
| --- | --- |
| 检索日志 | 数据库、时间、查询、筛选、结果、成功和失败记录 |
| 来源笔记 | 元数据、问题、设计、发现、限制、全文锚点、证据与审核状态 |
| 模型谱系表 | 前身、基准、假设变化、机制、新结果与依据 |
| 主张—证据台账 | 主张、类别、来源定位、证据等级、支持状态 |
| 验证计划 | 威胁、假设、现有与缺失证据、检验及对结论的影响 |
| 论文修改稿 | 有依据的主张、连贯段落、稳定术语与相称的研究含义 |
| 汇报或求助 brief | 听众与目的、可信发现、边界、材料及一个主要请求 |
| 阶段与反馈记录 | 当前阶段、变更理由、反馈决定、需回退部分和下一步 |

## 使用边界

本项目提供研究与写作指令及参考资料。检索需要可用的搜索或数据库工具；全文需合法可访问；Zotero、Obsidian 和文件格式处理需相应工具或技能。数据分析和实验执行不由本合集自动完成，研究设计的适用性也需独立证据。

尚未审核的核心笔记、缺失的全文、数据或识别前提，会限制依赖它们的综合和成稿。工作流会保留缺口，推进不依赖这些缺口的任务，并明确需要补充的材料或人工判断。
