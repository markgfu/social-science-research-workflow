# `full`：从想法到论文

`full` 是有回路的阶段状态机，不是按论文目录依次写作。优先完成能降低最大不确定性的工作。

进入精读、综合、成稿或反馈修改阶段时，加载 [作者判断与证据规范](author-judgment-writing.md)，遵守原文参照、判断与依据、论证取舍和内部质检要求。

## 状态与门槛

| 状态 | 核心产物 | 进入下一状态的最低条件 |
|---|---|---|
| 想法 | 现象、关系或问题草案 | 可说清研究对象与兴趣 |
| 候选问题 | 具体问题与边界 | 初步文献和证据可行性 |
| 文献发现 | 查询、候选集、排除记录 | 枢纽来源与主要术语已识别 |
| 阅读提取 | 带锚点的来源笔记 | AI 提取完成，标记 `waiting-review` |
| 人工审核 | 接受/修改/拒绝决定 | 核心笔记为 `accepted + A` |
| 综合与动机 | 文献生态、动机、claim ledger | 缺口已核验或标 `needs-search` |
| 数据/材料 | 样本与变量/材料账本 | 生成过程、限制和权限清楚 |
| 研究设计 | 目标、威胁、假设、实施 | 关键假设有验证计划 |
| 分析与验证 | 基准结果、威胁矩阵、拓展证据 | 失败结果与限制已登记 |
| 成稿与展示 | 闭环正文、图表和附录 | 强主张均有相称证据 |
| 反馈修改 | 反馈台账与版本决定 | 冲突意见已统筹、影响已复查 |

## 推进规则

1. 研究问题、关键文献、数据或设计变化时，生成“影响范围”：哪些模块、主张、图表和引用需要回退检查。
2. 保存研究问题、贡献、样本、变量和设计的版本，不覆盖变更理由。
3. 原始资料检索记录别名、范围、命中和未命中；“没有找到”不能编码为零或不存在。
4. 反馈拆成问题、证据要求、冲突、决定、负责人和状态；不要逐条盲从。
5. 只有当前门槛通过才进入依赖它的综合或成稿。用户可要求并行探索，但每条分支单独标记证据和状态。

## 阶段报告

每次只报告必要信息：当前状态、完成产物、证据等级、关键决定、未解决标记、回退触发器和下一项最小行动。长任务把这些写入持久工作记录，不依赖聊天历史。

## 完成定义

“完成一篇论文”不是所有模块都有内容，而是研究问题、文献动机、背景、数据/材料、设计与结果主张闭合；稳健性、异质性和机制按需要出现；引用、数据、结果和限制可追溯；人工审核及交付要求已满足。
